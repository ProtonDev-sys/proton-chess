# Exact node caps and stop-aware re-search

- Time: `2026-08-09T19:44:03+01:00`
- Branch: `agent/verifier-node-cap-2`
- Base: `origin/main` at `54168b0`
- Result: kept

## Problem

Retuning an evaluation fixture exposed a bounded-search overrun: a parent with a 4,100-node cap and 100 nodes already spent launched a restricted verifier with the remainder, then finished at 4,101. A standalone 4,000-node restricted search likewise reported 4,001. The existing full-strength 6,000-node regression encoded the same historical `limit + 1` behavior.

The immediate cause was not verifier arithmetic. Several search paths could return from a child that had set the sticky stop flag, interpret its aborted score, and enter another recursive search before checking the stop. Budgeting one or two fewer nodes only hid the behavior and had no proven maximum.

## Change

- Check `search_aborted()` after a razoring quiescence search before using its score or continuing.
- Check it after deep null-move verification before falling through to ProbCut or normal move search.
- Do not start ProbCut's reduced confirmation after an aborted quiescence search.
- Do not start LMR or full-window PVS re-searches after an aborted reduced/null-window search.
- Do not start a root full-window PVS re-search after an aborted null-window search.
- Give the restricted human verifier the exact remaining parent node budget.
- Keep a defensive fail-closed check: an unexpected child overrun is never accepted, and the parent counter saturates at its declared cap.

These gates affect only incomplete searches after a real stop or reserved main-budget exhaustion. Completed searches follow the same branches as before.

## Focused regressions

- Standalone start-position `searchmoves c2c4`, depth 8, 4,000 nodes: incomplete and exactly 4,000 nodes. Old code reports 4,001.
- Parent verifier starting at 100 nodes with a 4,100 total cap: incomplete, exact total 4,100, no candidate acceptance. Old code reports 4,101.
- Parent already at its cap: confirmation is declined and the counter is unchanged.
- Full-strength 6,000-node fixture: still `Qa7`, depth 5, now exactly 6,000 nodes instead of 6,001.
- Elo 3000 remains identical to full strength on the same bounded fixture.

The test-only peer calls the real private verifier; no production debug API was added.
