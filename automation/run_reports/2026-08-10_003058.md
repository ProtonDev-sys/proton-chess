## Problem

Earlier fixed-depth screens used one-off inline scripts. Their raw results were useful, but the command, timeout behavior, state reset, input staging and node semantics lived in run notes rather than in a reviewed tool. The old `benchmark_uci.py` timeout also wrapped a blocking `readline`, so a silent process could outlive the nominal deadline on Windows.

Fixed-node searches have a second trap. Proton prints an `info` line after each completed iterative-deepening pass. When the node cap stops the next pass, the last `info nodes` value is not the total number consumed against the cap. Treating it as a total can manufacture a node-saving claim.

## Change

Added `tools/compare_search.py` and its focused test suite.

The comparator:

- resolves, stages and hashes private copies of the candidate, baseline and opening suite;
- rejects identical paths, identical binary hashes, duplicate/invalid/terminal FENs and output/input path collisions;
- applies the same ordered full-strength option map to both engines, with `UCI_LimitStrength=false` last;
- starts fresh candidate and baseline processes for every trial;
- sends `ucinewgame` and waits for `readyok` before every position;
- asks Proton to echo the loaded FEN with `d` and requires an exact round trip before starting the clock;
- alternates candidate-first and baseline-first order by position and flips it on the next trial;
- drains combined stdout/stderr on reader threads and waits through a queue with a finite hard deadline;
- validates the requested depth, node cap, score shape, non-negative metrics, legal best move, legal reported PV and legal ponder move;
- requires best move, ponder, score, depth, selective depth, reported nodes and PV to repeat within each engine across trials;
- checkpoints JSON atomically after every completed search pair and retains failure context;
- attempts to close both engines even if the first cleanup fails;
- rehashes the staged and source inputs before accepting the run.

Depth mode reports node deltas only with an explicit warning that both revisions must use the same node-counting boundaries. Node-cap mode labels `info nodes` as the last completed iteration and never calculates a node-efficiency delta.

`matches/README.md` now documents both modes and their different interpretations.

## Focused regressions

The 13-test suite covers:

- default and explicit depth/node CLI parsing;
- uint64 node bounds, finite timeout bounds and the two-trial minimum;
- distinct labels and the ordered full-strength option map;
- strict, unique, canonical six-field FEN loading;
- centipawn and mate scores;
- malformed bestmove/ponder lines, contradictory bounds and invalid metrics;
- legal PV/root consistency and exact requested depth;
- queue timeouts against a silent process;
- exact FEN echo before search;
- position/trial order reversal;
- fixed-depth summary math and fixed-node omission of efficiency deltas;
- ponder-sensitive repeatability;
- source mutation during staging and atomic JSON replacement;
- fresh process use, complete checkpoints and failed-run context;
- cleanup of the second engine after the first close fails;
- cleanup notes and a closed stdout pipe after a complete report.
