## Problem

The existing Elo estimator used a fixed `movetime` for every move, reused engine state across games, had no watchdog for clock-only searches, and emitted only aggregate scores. It could not run the required `60+0.6` protocol or preserve enough evidence to reproduce a match.

It also published a normal-approximation confidence interval that treated paired games as independent. Two draws produced a false zero-width `3000-3000` interval.

## Change

- Added mutually exclusive fixed-movetime and Fischer-clock modes. The target syntax is `--base-seconds 60 --increment 0.6`.
- Added exact wall-clock accounting, flag adjudication before increment, and configurable watchdog grace.
- Added an async UCI watchdog that cancels a stuck play command and closes the process.
- Opened fresh Proton and Stockfish processes for every game.
- Bound a distinct game token and completed `ucinewgame`/`isready` before timed play.
- Added deterministic opening scheduling with the selected opening index in every record.
- Added raw moves, clocks and termination reasons for every game.
- Added engine IDs/options/hashes, opening/tool hashes, Git revision/dirty state, Python versions, and host details to schema version 1.
- Removed the invalid legacy confidence interval. Pair-aware inference will be added separately.
- Added nine focused clock, flag, timeout, schedule, and lifecycle tests.
- Made the CMake test conditional on python-chess availability for local builders.
