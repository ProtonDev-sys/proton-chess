## Problem

An immediate UCI `stop` could be lost during worker startup. `start_search` exposed the worker to the input loop before `Search::think` cleared its stop flag. If the input thread handled `stop` in that window, the worker overwrote the request with `false`; `stop_search` then blocked while joining an infinite search.

The existing test waited for an `info` line before sending `stop`, guaranteeing that worker startup had finished and masking the race.

## Failing baseline

Three independent transcripts each queued eight copies of:

```text
position startpos
go infinite
stop
```

All three engine processes timed out instead of exiting.

## Change

- Added an optional one-shot `StartCallback` to `Search::think`.
- Fired the callback immediately after the search worker's final `stop_requested_ = false` reset.
- Added a promise/future handshake in the UCI layer so `start_search` returns only after that point.
- Added a pre-buffered UCI regression covering 16 immediate normal stops and four immediate ponder stops. The test does not wait for search output before cancelling.
