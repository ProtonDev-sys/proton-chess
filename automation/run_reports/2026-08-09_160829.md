## Problem

The limiter had four correctness failures:

- UCI setters changed unrelated custom state, so replaying advertised defaults enabled human play.
- Elo 800 could select from root PVS bounds that had never been verified.
- A cancelled verification could be treated as evidence for a candidate.
- Timed limited play could return a full-strength book move before the limiter ran.

The loss-band failure was reproducible from:

```text
3rk3/ppp2ppp/8/8/3Q4/8/PPP2PPP/4K3 w - - 0 1
```

At depth 4, full search chose `Qa7` at `+677`. Elo 800 with seed 27 chose `a3`; an independent `searchmoves a3` run scored it `-595`. The actual 1,272 cp loss exceeded the configured 700 cp allowance.

## Change

- Added independent `uci_limit_strength` and `uci_elo` state.
- Made `UCI_LimitStrength`, `UCI_Elo`, `Skill Level`, `HumanStyle` and `HumanSkill` setters change only their own setting.
- Centralized effective limiter resolution: enabled UCI limiting takes precedence, otherwise explicit human style or a custom skill below 20 enables custom limiting.
- Used a TT-independent PV-style narrow search to filter the non-best candidate pool.
- Restored the root move-stack context before each filter search.
- Re-searched a sampled alternative in a fresh isolated 1 MB verifier at the same depth with `searchmoves`; only `candidate >= best - allowance` is accepted.
- Shared the parent stop flag, hard deadline and remaining node budget with the verifier. Incomplete or interrupted confirmation falls back to the best move.
- Limited retries to three sampled alternatives before falling back to best.
- Disabled the opening-book early return whenever either limiter mode is active.
- Added native and raw-UCI regressions for loss bounds, real node-limit interruption, book bypass, default replay, skill round trips and non-vacuous UCI/custom independence.
