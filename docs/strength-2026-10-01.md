## Engine changes tried

- Safe mobility excludes squares attacked by enemy pawns.
- King-ring pressure combines the number and strength of coordinated attackers,
  with a nonlinear middlegame term and reduced pressure without a queen.
- Passed-pawn conversion considers blockers, a clear/safe promotion path, and
  both kings' distance to the front square. Dynamic terms remain outside the
  pawn-only cache.
- Conservative singular extensions verify alternatives to a sufficiently deep
  transposition-table move, with bounded extension eligibility. Excluded-move
  verification cannot use a full-position TT cutoff or overwrite that entry.
- A genuine TT replacement bug is fixed: an unrelated position no longer
  inherits a stale move when the replacement store has no move. A same-position
  store without a move still preserves its remembered move.
- Optional native CPU compilation is tested separately from algorithm changes;
  portable builds remain the default. The release version is now 0.3.0.

## Reproducibility and fairness

- Original source: commit `282f012`; frozen candidate source: commit `0034f0b`.
- Hardware: AMD Ryzen 7 9800X3D, 8 physical cores / 16 logical processors,
  Windows, MSVC 19.44 Release with LTO. Candidate confirmation uses AVX2 native
  compilation. Source-built native executable matches the frozen binary hash.
- Official latest stable release verified: Stockfish 19, tag `sf_19`, published
  September 5, 2026 at 08:33:17 UTC. Official Windows universal archive digest is
  checked against the release API. Stockfish's `compiler` command selects
  `x86-64-avx512icl` on this host; this is not an unoptimized fallback executable.
- Candidate SHA-256:
  `1ea5e0c671ec977655282ad127a0b76ff664e45fc2ccb64a17a09555dde77463`.
- Stockfish SHA-256:
  `45bc8e4969147db9c2eb533810637994619bff0eacc81ccfd9854394901bcbd0`.
- Opening-suite SHA-256:
  `d58775f05e0eaf50703f648bf20f93522cf8841fcadf0537a6520c5da44c5ae8`.
- Both engines use one thread, 64 MiB hash, books off, 1 ms configured move
  overhead, and candidate strength limiting/human style off. The 50-opening
  suite is independent of the longer playing book. Openings are sampled with
  replacement and played with reversed colors, with fresh game state.
- Confirmation uses six pair workers at 100 ms and four at 250 ms. Ladder and
  native self-play use two workers. Different experiments ran concurrently;
  elapsed timing and weakened-engine outcomes depend on shared host load.
- A game's ply cap is 800. A nonterminal capped game remains unresolved; an
  illegal move or engine failure fails a run instead of inventing a result.
- Hoeffding bounds use pair count, not twice that count. The opening seed
  controls opening draws, not Stockfish's internal weakened-play randomness.
  Fresh confirmation seeds are fresh samples from the same finite suite, not
  a claim of generalization to previously unseen opening families.

## Next ideas, not yet implemented

1. Tune the new mobility, king-pressure, passer, and singular-extension parameters
   in small ablations. Require native-versus-native self-play confirmation rather
   than trusting a favorable small Stockfish screening score.
2. Profile and reduce move-ordering/attack-generation cost before adding more
   pruning. Measure fixed-node throughput and retain tactical/draw-rule tests.
3. Add incremental learned evaluation with licensed training positions and an
   independently validated inference path. This is a larger project, not a
   cosmetic replacement for the current handcrafted evaluator.
4. Add endgame-tablebase integration and focused pawn-ending/zugzwang regression
   suites; test conversion separately from opening strength.
5. Investigate parallel search only after a single-thread baseline is stable.
   Compare equal resource budgets, not extra candidate cores against one opponent
   core, and check reproducibility and TT synchronization.
6. Freeze the next candidate and preregister a fresh 2400 confirmation at both
   time controls. Keep the same conservative confidence gate and report losses
   against higher/unrestricted settings, not just successful difficulty levels.
